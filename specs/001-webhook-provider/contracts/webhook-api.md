# Contract: ExternalDNS webhook provider API

**Feature**: [../spec.md](../spec.md) | **Date**: 2026-09-04

本サービスの外部インタフェースは ExternalDNS webhook provider API そのものである。
**正典は上流の OpenAPI 仕様** (`kubernetes-sigs/external-dns` v0.22.0 の `api/webhook.yaml`)
であり、本書はそれを実装側から見た契約として整理したものである。両者が食い違う場合は
上流仕様が優先する (原則 I)。

独自のエンドポイント・フィールドを追加しない (MUST NOT)。

---

## メディアタイプ

```
application/external.dns.webhook+json;version=1
```

- リクエストの `Accept` ヘッダを読み、レスポンスの `Content-Type` に同じ値を設定する
- このメディアタイプでネゴシエートできない要求は受け付けない

---

## provider エンドポイント (既定 `8888`、ループバックのみ)

### `GET /` — 管理対象ドメインのネゴシエーション

ExternalDNS が起動時に呼び、本 provider が扱うドメインの範囲を得る。

| 項目 | 内容 |
|---|---|
| 成功 | `200` |
| 応答 | 管理対象ドメインの情報 |
| 失敗 | `500` |

**契約テストで固定する振る舞い**:

- 管理対象ドメインが未設定のとき、**空の範囲**を返す。全ドメインを表す応答を返さない
  (FR-002)
- 応答に含めるドメイン名の表現は上流仕様に従う

### `GET /records` — レコード一覧の取得

| 項目 | 内容 |
|---|---|
| 成功 | `200` |
| 応答 | レコードの配列 |
| 失敗 | `500` |

**契約テストで固定する振る舞い**:

- 管理対象外のレコードを含めない (FR-006)
- 対応リスト外の種別を含めない (FR-027)。**`NS` を含めない** (FR-029)
- **読み取り元ゾーンがその名前の帰属先でないレコードを含めない** (FR-044)。
  親ゾーン側に残った値と子ゾーン側の権威レコードが、同じ名前・種別で 2 件返る状態を
  作らない
- 名前は**小文字かつ末尾ドットなし**で返す (MUST)。末尾ドットを付けない (MUST NOT)。
  ExternalDNS の TXT レジストリが所有権レコードの有無を**素の文字列一致**で照合する
  ため、ドット付きでは必ず外れて差分が振動する (research R7 の訂正)。
  内部表現と DPF へ渡す値は正規化名 (末尾ドット付き) のままである
- `setIdentifier`・`labels`・`providerSpecific` は**空のまま返す**。本 provider は
  これらを保持しないため、あるかのように返さない。ExternalDNS の TXT レジストリは
  所有権ラベルを TXT レコードから導くので、これで困らない。**調整の応答とは扱いが
  異なる** (上記 `POST /adjustendpoints`)

### `POST /records` — 変更の適用

| 項目 | 内容 |
|---|---|
| 成功 | **`204 No Content`** |
| 要求 | 作成・更新・削除の対象レコード |
| 失敗 | `4xx` (恒久的) / `5xx` (一時的) |

**契約テストで固定する振る舞い**:

- 成功時の状態コードは `200` ではなく `204`
- 空の変更セットは何も変更せず成功とする
- `NS` を含む要求は恒久的な失敗 (`4xx`) とする。未対応の種別として扱う
  (FR-029、FR-028)
- 1 つの要求が複数のゾーンにまたがる場合、ゾーンごとに適用する。名前の帰属先は
  最長一致で決まる (FR-040)。いずれかのゾーンで失敗すれば要求全体を失敗とする
  (FR-042)
- 反映が完了する前に成功を返さない (FR-011)
- 部分的にしか成功しなかった場合、成功を返さない (FR-012)
- 受け取った名前は、末尾ドットの有無や大文字小文字によらず同一のレコードとして扱う。
  受信時に正規化するため、上流の表現に依存しない (research R7)

### `POST /adjustendpoints` — プロバイダ固有の調整

| 項目 | 内容 |
|---|---|
| 成功 | `200` |
| 要求 | 調整前のレコード |
| 応答 | 調整後のレコード |
| 失敗 | `500` |

**契約テストで固定する振る舞い**:

- 冪等であること。調整済みの入力に対して出力が変化しない (FR-015)
- 調整不要の入力はそのまま返る
- **解釈しないフィールド (`setIdentifier`、`labels`、`providerSpecific`) を、
  受け取った値のまま返す (MUST)。落とさない (MUST NOT)。**
  上流の `AdjustEndpoints` は**返された配列で入力を差し替える**
  (`BaseProvider` の既定が `return endpoints, nil` であることがその前提を示す)。
  落とすと ExternalDNS 自身が組み立てた情報が消える。

  実害が出たのは `labels` である。ExternalDNS は Ingress 由来の
  `external-dns/resource=...` をここに載せ、TXT レジストリの所有権レコードを
  このラベルから組み立てる。落とすと DPF 上の所有権 TXT から `resource` が
  欠ける (実環境で確認)。

  上流のサーバ側ヘルパ (`provider/webhook/api/httpapi.go`) は
  `[]*endpoint.Endpoint` を直接 decode/encode するため、この問題が起きない。
  本 provider は転送形を自前で定義しているぶん、明示的に保つ必要がある

## エラーの区別

| 状況 | 状態コード | ExternalDNS の期待する挙動 |
|---|---|---|
| 一時的な障害 (DPF の応答不能、レート制限、ロック取得不能) | `5xx` | 再試行する |
| 恒久的な障害 (形式違反、未対応種別、ゾーン解決不能、トークン取得失敗) | `4xx` | 再試行しない |

**一時的な障害を `4xx` として返さない (MUST NOT)。** ExternalDNS の再試行判断を
誤らせ、復旧可能な障害が復旧しなくなる。

## exposed エンドポイント (既定 `8080`)

| エンドポイント | 用途 | 必須 |
|---|---|---|
| `GET /healthz` | liveness / readiness probe | MUST |
| `GET /metrics` | Prometheus 形式のメトリクス | MUST (上流では optional。原則 V により必須) |

**セキュリティ上の前提**: この 2 つは同一ポートで提供されるため、NetworkPolicy で
区別できない。probe を通す設定は同時に `/metrics` を同じ送信元へ露出させる。
したがって `/metrics` のラベルにゾーン名・レコード名・レコード値を既定で含めない。

**返してよい情報の範囲**: healthz と metrics に限る。DNS 構成が推測できる情報を
認証なしで返さない。

## 契約テストの位置づけ

原則 I により、**契約テストが仕様の唯一の実行可能な表現**である。

- 仕様の解釈が必要な箇所は、実装コードではなく契約テストに落とす
- 上流仕様の変更に追随する場合は、まず契約テストを更新し、その差分をレビュー対象とする
- 上流がメディアタイプの `version` を変更した場合、自動追随しない。constitution を
  改訂したうえで方針を決める
