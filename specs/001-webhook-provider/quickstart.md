# Quickstart: 動作確認の手順

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Date**: 2026-09-04

本書は、実装が spec の受け入れ条件を満たすことを確認するための手順をまとめる。
実装コードは含まない。詳細は [contracts/](./contracts/) と [data-model.md](./data-model.md)
を参照。

---

## 前提

| 項目 | 内容 |
|---|---|
| Go | 1.27 以降 |
| コンテナ | podman または docker |
| DPF | 破壊的操作を行ってよい**検証用ゾーン**と、そのゾーンを操作できるアクセストークン |
| ExternalDNS | v0.22.0 以降 (end-to-end 確認時のみ) |

**警告**: US2 以降の確認は DNS レコードを実際に変更する。本番ゾーンでは実行しない。

## 1. コード品質ゲート

constitution が CI ゲートとして要求する項目。ローカルでも同じ内容を実行できる。

```bash
gofmt -l ./...          # 出力が空であること
go build ./...
golangci-lint run
govulncheck ./...
go test ./...
```

`gofmt -l` が何か出力したら、整形されていないファイルがある。議論せず `gofmt -w` を適用する。

---

## 2. ビルドと ASLR の検証

ASLR が有効であることは CI ゲートの 1 つ (constitution v1.6.0)。

```bash
podman build -t external-dns-iij-dpf-webhook -f build/Containerfile .
```

生成されたバイナリが **static PIE** であることを確認する。

```bash
# ELF Type が DYN であること (= PIE、ASLR 有効)
readelf -h <binary> | grep Type

# PT_INTERP が無いこと (= 静的、scratch で動作可能)
readelf -l <binary> | grep INTERP && echo "NG: 動的リンク" || echo "OK: 静的"
```

**期待値**: `Type: DYN`、`INTERP` なし。

`CGO_ENABLED=0` でビルドすると、この 2 つを同時に満たせない
([research.md R1](./research.md) の表を参照)。

## 3. 既定設定の安全性 (原則 VI)

引数なしで起動し、既定が拒否側であることを確認する。

| 確認 | 期待される結果 |
|---|---|
| トークン未設定で起動 | 起動せず異常終了する (FR-017) |
| 設定値が解釈できない | 既定値で続行せず異常終了する (FR-018) |
| domain filter 未設定で起動 | 起動する。管理対象が空である旨をログに出す |
| domain filter 未設定でレコード一覧を取得 | **0 件**が返る (FR-002) |
| provider ポートの待ち受け | ループバックのみ。Pod 外から到達できない |

domain filter 未設定時に全件が返る場合、default-deny が破れている。

## 4. User Story 1: 管理対象の宣言とレコードの把握

**DNS を変更しないため、本番ゾーンに対しても安全に実行できる。**

```bash
# 検証用ゾーンを管理対象に設定して起動し、provider エンドポイントへ問い合わせる
```

| 確認 | 期待される結果 |
|---|---|
| 管理対象ドメインの問い合わせ | 設定したドメインが返る |
| レコード一覧の取得 | 管理対象ゾーンのレコードのみが返る |
| 管理対象外ゾーンのレコード | 一覧に含まれない (FR-006) |
| 大文字混じりで登録された名前 | 同一の名前として管理対象に含まれる (FR-004) |
| 返される名前の表現 | 正規化名 (小文字・末尾ドット) である |
| 末尾ドットの有無が異なる名前を適用要求に含める | 同一のレコードとして扱われる |
| `CAA` や `ANAME` のレコード | 一覧に含まれない (FR-027) |
| DPF が応答しない状態 | `5xx` が返り、`4xx` にはならない |

## 5. User Story 2: レコードの作成・更新・削除

**検証用ゾーンでのみ実行する。**

| 確認 | 期待される結果 |
|---|---|
| 未登録の名前を作成 | DPF に作成され、名前解決できる |
| 既存の名前を更新 | 値が置き換わる |
| 登録済みの名前を削除 | DPF から削除される |
| **同じ変更セットを 10 回連続で適用** | 最終状態が変わらず、エラーにもならない (SC-002) |
| 管理対象外のドメインを含む変更 | そのレコードは変更されず、他は処理される (FR-009) |
| 空の変更セット | 何も変更せず成功 |
| 適用の成功応答 | `204 No Content` (`200` ではない) |

**反映完了の確認 (FR-011)**: 適用が成功を返した直後に DPF 側を参照し、
**保留状態ではなく公開済み**になっていることを確認する。保留のまま成功が返る場合、
反映の待ち合わせが実装されていない。

**管理対象外レコードの保全 (最重要)**: 適用はゾーン全体を一括更新する方式のため、
管理対象外のレコードが巻き添えで消えないことを必ず確認する。

| 手順 | 期待される結果 |
|---|---|
| 検証用ゾーンに `CAA` `TLSA` `ANAME` などを手動で登録しておく | — |
| その状態でレコードの作成・更新・削除を一通り実行 | **これらが 1 件も変更・削除されない** (FR-027) |
| 管理対象外の名前 (範囲外) のレコードを登録しておく | 同上 (FR-009、SC-004) |
| 適用後に各レコードの TTL・値・コメント・ラベルを比較 | **すべて元のまま**である |

コメントやラベルが失われる場合、逐語コピーではなくドメインモデルを経由している。

**投入前ガード**: マージ結果が変更セット外のレコードを削除する内容になったとき、
適用が中止され一時的な失敗が返ることを確認する。

**ロックの範囲**: レコード取得の要求だけを行い、適用要求を送らずに放置する。

| 確認 | 期待される結果 |
|---|---|
| 取得のみ実行して放置 | ゾーンロックが取得されない、または残留しない |
| その後に別経路でゾーンを操作 | 操作できる (ロック残留でブロックされない) |

取得要求がロックを取って保持していると、適用が来ないままゾーンが操作不能になる。

**ゾーン規模**: 1,000 件規模のレコードを持つゾーンで適用が成功することを確認する。

**保留変更の破棄 (PC-004)**: DPF コンソールでレコードを編集し、**反映せずに保留したまま**
適用を実行する。

| 確認 | 期待される結果 |
|---|---|
| 適用の成否 | 中止されず成功する |
| 保留していた編集 | 破棄される (権威 DNS には公開されない) |
| 保留していた編集の内容 | 適用結果に**含まれない** (未レビューの編集が公開されない) |

適用が中止される実装になっていると、下書きの放置で DNS の更新が恒久的に止まる。

破棄の記録は DPF サービス側のログを参照する。本 provider は検出も記録も行わないため、
そのためだけの API 呼び出しが発生していないことも併せて確認する。

**種別ごとの制約**:

| 入力 | 期待される結果 |
|---|---|
| 名前に `_` を含む `A` レコード | DPF へ送る前に恒久的な失敗 (FR-031) |
| 同一名に `CNAME` と他種別 | 恒久的な失敗 (FR-030) |
| 256 オクテットの character-string 1 個からなる `TXT` | **自動分割されて登録される** (FR-032) |
| `"STR1" "STR2"` 形式で合計 255 オクテット超の `TXT` (DKIM 鍵など) | **正常に登録される** (FR-032) |
| 上記を取得して書き戻す | **分割位置が変わらない** (FR-032a) |
| 引用符を含まない `v=spf1 -all` | **1 つの character-string として登録される** (FR-032b) |
| ゾーン apex の `NS` の作成・更新・削除 | DPF へ送る前に恒久的な失敗 (FR-029) |
| `DNAME` レコード | 適用されない (FR-028) |

## 6. User Story 3: 調整の冪等性

| 確認 | 期待される結果 |
|---|---|
| DPF が許容しない TTL を渡す | 許容範囲に補正されて返る |
| **調整結果を再度調整に掛ける** | 内容が変化しない (FR-015) |
| 調整不要の入力 | そのまま返る |

調整が冪等でないと、ExternalDNS が同じ差分を検出し続ける (SC-007)。

## 7. User Story 4: 可観測性

| 確認 | 期待される結果 |
|---|---|
| `/healthz` | 稼働中に正常を返す |
| `/metrics` | Prometheus 形式で取得できる |
| レコード変更後の計測値 | 成否と件数が反映される (FR-021) |
| OTLP 送出先を未設定で起動 | **送出しない**。標準出力へのログは出る |
| OTLP 送出先を設定 | メトリクスとトレースが送出される |
| OTLP 送出先を到達不能にする | **DNS の更新は継続する** (FR-024) |
| 要求 1 件のトレース | 受信から DPF 呼び出しまでが 1 つの流れとして繋がる (FR-022) |

**秘匿情報の確認 (SC-006)**: 一連の操作の後、ログ・メトリクス・トレース・
エラーメッセージのいずれにもトークンが現れないことを確認する。

```bash
# 出力にトークン文字列が含まれないこと
<出力> | grep -F "$(cat <token-file>)" && echo "NG: トークンが漏れている" || echo "OK"
```

**メトリクスのラベル**: `/metrics` の出力にゾーン名・レコード名・レコード値が
既定で含まれないことを確認する。`/metrics` は probe と同一ポートで公開されるため。

## 8. トークンのローテーション (SC-009)

| 手順 | 期待される結果 |
|---|---|
| 稼働中にトークンファイルの内容を差し替える | **再起動なしで**次の要求から新しいトークンが使われる (FR-037) |
| トークンファイルを削除する | 恒久的な失敗として扱われ、再試行を繰り返さない (FR-038) |
| トークン取得失敗時のエラーメッセージ | トークン値やファイル内容を含まない (FR-039) |

## 9. end-to-end 確認

ExternalDNS と本 provider をサイドカー構成で動かし、実際の流れを確認する。

| 手順 | 期待される結果 |
|---|---|
| 検証用ゾーンのホスト名を持つ Ingress を作成 | **5 分以内**に DPF 上にレコードが反映される (SC-001) |
| その状態でしばらく放置 | 同じ差分が繰り返し適用されない (SC-007) |
| Ingress を削除 | 対応するレコードが削除される |
| 管理対象外ゾーンのレコード | 全操作を通じて 1 件も変更されない (SC-004) |
