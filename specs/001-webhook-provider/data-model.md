# Data Model: ExternalDNS webhook provider 本体

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Date**: 2026-09-04

本サービスは永続状態を持たない。ここで定義するのは、要求を処理する間だけ存在する
実体と、境界をまたぐときの変換規則である。

---

## 1. 正規化名 (Canonical Name)

ドメイン名を保持する唯一の内部表現。小文字かつ末尾ドットで終わる FQDN。

| 属性 | 内容 |
|---|---|
| 値 | `dns.CanonicalName` の出力 |
| 生成 | 境界での変換時のみ。生の文字列から直接構築させない |
| 検証 | 生成時に `dns.IsDomainName` で妥当性を確認。失敗した名前は実体化しない |

**不変条件**: 実体化された正規化名は、必ず正規化済みである。この保証があるため、
比較は値の比較で足り、呼び出しごとに大文字小文字を無視する比較関数を使う必要がない。

**操作**:

| 操作 | 用いる関数 | 用途 |
|---|---|---|
| 包含判定 | `dns.IsSubDomain` | 管理対象かどうか (FR-003) |
| ラベル分割 | `dns.SplitDomainName` | ゾーンとの相対名の算出 |
| ラベル数 | `dns.CountLabel` | 最長一致ゾーンの選択 |

**禁止**: `strings.HasSuffix` / `TrimSuffix` / `Split` / `EqualFold` / `ToLower` による
これらの代替 (constitution v1.4.0)。

---

## 2. 管理対象範囲 (Domain Filter)

本 provider が操作を許される名前の集合。

| 属性 | 内容 |
|---|---|
| 対象ドメイン | 正規化名の集合。空を許す |
| 未設定時の意味 | **範囲なし**。いかなる名前も含まない (FR-002) |

**判定**: ある正規化名 N が範囲に含まれるのは、対象ドメインのいずれか D について
`dns.IsSubDomain(D, N)` が真のときに限る。集合が空なら常に偽。

**不変条件**: 「空集合 = 全許可」への読み替えを行わない。この誤読が原則 VI の
default-deny を破る最短経路である。

---

## 3. 管理対象ゾーン (Managed Zone)

DPF 上に存在し、本 provider が操作するゾーン。

| 属性 | 内容 |
|---|---|
| ゾーン名 | 正規化名 |
| ゾーン ID | DPF がゾーンを識別する値 |
| 状態 | 反映可能か、保留変更を持つか |

**解決**: ある正規化名を書き込む先のゾーンは、管理対象ゾーンのうち
`dns.IsSubDomain` を満たし、かつラベル数が最大のもの (最長一致) とする。
該当がなければ、そのレコードは管理対象外である。

**制約**: 本 provider はゾーンを作成しない (FR-013)。解決できないゾーンへの要求は
恒久的な失敗とする。

## 4. DNS レコード (Record)

| 属性 | 内容 | 制約 |
|---|---|---|
| 名前 | 正規化名 | — |
| 種別 | 許可リストの 9 種別のいずれか | FR-026 |
| 値 | 文字列の集合 | 種別ごとに形式が異なる |
| TTL | 整数 | DPF の許容範囲に収める (FR-014) |

### 種別の対応付け

| ExternalDNS | DPF | 扱い |
|---|---|---|
| `A` `AAAA` `CNAME` `TXT` `SRV` `NS` `PTR` `MX` `NAPTR` | 同名の種別 | 対応する |
| `DNAME` | なし | 適用しない (FR-028) |
| — | `SOA` `ANAME` `CAA` `DS` `HTTPS` `SVCB` `TLSA` | 読み飛ばす。変更しない (FR-027) |

### TXT の表現

`TXT` は他の種別と異なり、**1 つのレコードの値が複数の character-string からなりうる**。

```
example.jp. IN TXT "STR1" "STR2"
```

| 事項 | 内容 |
|---|---|
| 制限 | character-string 1 個あたり 255 **オクテット** |
| 合計長 | 制限しない。255 を超えるのは正常 (DKIM 鍵など) |
| 単位 | 文字数ではなくオクテット数。マルチバイト文字で差が出る |
| DPF 側の表現 | `Rdata` の 1 要素の `value` に、引用符で区切った表現形式で格納される |

**不変条件**: 分割された状態を保つ (FR-032a)。読み取り時に連結せず、書き込み時に
分割位置を変えない。連結すると 255 オクテット制限に抵触して登録できなくなり、
分割位置を変えると受信側が解釈する値が変わる。

**注意**: DPF の API スキーマは `value` に長さ制約を宣言していない。255 オクテットの
検証は本 provider 側で行う。

### 種別ごとの検証規則

DPF へ送る前に検証し、満たさないものは恒久的な失敗とする。

| 規則 | 対象 | 要件 |
|---|---|---|
| 名前にアンダースコアを含まない | `A` `AAAA` | FR-031 |
| 単一値であり、同名に他種別が共存しない | `CNAME` | FR-030 |
| character-string 1 個が 255 オクテット以下。**合計長は制限しない** | `TXT` | FR-032 |
| preference が 0〜65535 | `MX` | FR-033 |
| priority / weight / port が 0〜65535 | `SRV` | FR-033 |
| ゾーン名と同じ名前は削除しない | `NS` | FR-029 |

## 5. 変更セット (Change Set)

ExternalDNS が算出した、作成・更新・削除の対象レコードのまとまり。
**適用は変更セット単位で成否が決まる。**

| 属性 | 内容 |
|---|---|
| 作成 | 追加するレコード |
| 更新 | 置き換えるレコード (適用前・適用後の対) |
| 削除 | 取り除くレコード |

### 適用の状態遷移

```text
  受領
   │
   ├─ 範囲判定 ──[範囲外を含む]──→ 範囲外を除外
   │
   ├─ 種別・形式の検証 ──[違反]──→ 恒久的な失敗 (4xx)
   │
   ├─ ゾーン解決 ──[解決不能]──→ 恒久的な失敗 (4xx)
   │
   ├─ ゾーンロック取得 ──[取得不能]──→ 一時的な失敗 (5xx)
   │   ※ ロックはここから解放までの区間に限る。
   │     レコード取得の要求 (別の HTTP 要求) はロックしない
   │
   ├─ 反映済みレコードの全件取得 ──[失敗]──→ 一時的な失敗 (5xx)
   │   ※ マージの土台はここで読み直す。以前に返した一覧は使わない
   │     編集中を含む一覧は用いない (他者の未レビュー編集を公開しないため)
   │
   ├─ マージ (管理対象は変更を適用、管理対象外は逐語コピー)
   │
   ├─ 投入前ガード ──[変更セット外の削除を検出]──→ 中止・一時的な失敗 (5xx)
   │
   ├─ 一括更新 + ゾーン反映 (原子的) ──[失敗]──→ 失敗 (状態は変わらない)
   │
   ├─ 反映完了の待ち合わせ ──[失敗/時間切れ]──→ 失敗
   │
   └─ ロック解放 → 成功 (204)
```

**不変条件**:

- 「反映完了の待ち合わせ」を通過する前に成功を返さない (FR-011)
- いずれかの段階で中止した場合、成功として返さない (FR-012)
- 範囲外のレコードは、除外されるのであって、失敗を引き起こさない
- 空の変更セットは、何も変更せずに成功とする
- 更新と反映は原子的に行われるため、**保留状態が発生しない**。中断時に巻き戻す対象が
  存在しない

### マージの規則

一括更新は渡さなかったレコードを削除する。したがって投入する集合は
**ゾーンのあるべき全体**でなければならない。

| 対象 | 扱い |
|---|---|
| 管理対象かつ変更セットに含まれる | 変更後の内容を投入。現在値が変更セットの「更新前の値」と食い違っていても、変更後の内容を優先する |
| 管理対象だが変更セットに含まれない | 現在の内容をそのまま投入 |
| 管理対象外 (範囲外の名前、対象外の種別) | **読み取った値を逐語的にコピー**して投入 |
| SOA、ゾーン apex の NS | 投入しない。API 側の既定 (上書きしない) に委ねる |
| ゾーンに残っていた未反映の編集 | 一括更新により破棄される。有無を調べず、記録もしない (FR-020a、PC-004) |

**管理対象外のレコードは本プロジェクトのドメインモデルを通さない (MUST NOT)。**
種別の対応付けや正規化を経由させず、読み取った表現のまま書き戻す。変換を挟まなければ、
変換の誤りが管理対象外のレコードを壊すことはない。

### 投入前ガード

マージ結果を投入する前に検証する。

**条件**: 投入する集合から失われるレコードが、変更セットの削除対象と完全に一致すること。

一致しない場合は適用を中止し、一時的な失敗とする。これにより、マージの誤りは
「レコードが消える」ではなく「適用されない」として現れる (原則 IV の fail closed)。

**冪等性**: 同じ変更セットの再適用は、DPF 上の最終状態を変えない (FR-010)。
作成済みのレコードの作成要求、および存在しないレコードの削除要求は、
いずれも最終状態を変えない操作として扱う。

## 6. アクセストークン (Access Token)

| 属性 | 内容 |
|---|---|
| 取得元 | マウントされたファイル、または外部シークレット管理サービス |
| 評価 | **要求のたびに評価される**。固定値として保持しない |
| 失敗時 | 恒久的な失敗。再試行を繰り返さない (FR-038) |

**不変条件**: 値がログ・計測値・追跡情報・エラーメッセージのいずれにも現れない
(FR-039、SC-006)。

**ローテーション**: 取得元の内容が外部で更新されると、次の要求から新しい値が使われる。
再起動を要しない (FR-037)。

## 7. 計測値 (Telemetry)

計測器は 1 組だけ定義し、Prometheus 形式と OTLP の両方へ同じ値を流す
(原則 V、research R8)。

| 計測 | 内容 |
|---|---|
| レコード変更操作 | 成否と件数 (FR-021) |
| DPF 呼び出し | 成否と所要時間 |
| 追跡 | 要求受信から DPF 呼び出しまでを 1 つの流れとして接続 (FR-022) |

**ラベル・属性の制約**: ゾーン名・レコード名・レコード値を既定で含めない
(原則 V)。基数が非有界であり、かつ `/metrics` は probe と同一ポートで公開されるため。
ログへの記録はこの制限の対象外であり、FR-020 のとおり対象を記録する。
