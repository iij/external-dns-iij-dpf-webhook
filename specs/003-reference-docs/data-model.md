# Data Model: リファレンス文書

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Date**: 2026-09-10

本機能はデータを永続化しない。ここで定めるのは、検査が扱う概念と、それらの間の
規則である。

---

## 1. 検査対象 (Checked Set)

文書の表 1 つと、実装から取り出した事実 1 組の対応。

| 項目 | 内容 |
|---|---|
| 印 | 文書中の HTML コメント。`<!-- reference:<名前> -->` |
| 名前 | 対象を識別する語。`flags` / `secret-managers` / `metrics` / `dpf-operations` / `record-types` / `endpoints` |
| 文書側の値 | 印の直後の表から取り出した値の集合 |
| 実装側の値 | 実装から取り出した値の集合 |
| 突き合わせ | 両者が集合として一致すること |

### 6 つの検査対象

| 名前 | 文書側 | 実装側の源 |
|---|---|---|
| `flags` | 設定項目の表の第 1 列 (名前) と第 2 列 (既定値) | `config.Usage()` の出力 |
| `secret-managers` | 供給元の比較表の第 1 列 | `config.Load` が受理する値 |
| `metrics` | 計測値の表の第 1 列 | Prometheus 形式の出力に現れる系列名 |
| `dpf-operations` | `operation` ラベルの値の一覧 | `internal/dpf` で `observe` に渡される文字列リテラル |
| `record-types` | 対応レコード種別の一覧 | `provider.SupportedRecordTypes()` |
| `endpoints` | 経路の表の第 2 列 (経路) | `internal/webhook` と `internal/server` で `mux.Handle` / `mux.HandleFunc` に渡される文字列リテラル |

### 不変条件

- **6 つの印がすべて文書に存在すること。** 1 つでも欠ければ検査は失敗する
  (research R3)。「対象がないので何も検査しない」で通さない
- 文書側と実装側は**集合として**一致すること。文書にあって実装にないもの、
  実装にあって文書にないもの、どちらも失敗とする (SC-004、SC-005)
- 検査対象の一覧は**検査側のコードに持つ**。文書側に持たせない。文書を
  書き換えるだけで検査を緩められる状態にしない
- 表の行が 0 件の場合は失敗とする。表を空にすることで検査を通せない

## 2. 印 (Marker)

```markdown
<!-- reference:flags -->
| フラグ | 既定 | 内容 |
|---|---|---|
| `--domain-filter` | (なし) | 管理対象ドメイン... |
```

| 項目 | 内容 |
|---|---|
| 形 | `<!-- reference:<名前> -->` を単独の行に置く |
| 位置 | 対象の表の**直前**。間に空行があってよい |
| 役目 (機械) | 解析器に検査対象を伝える |
| 役目 (人) | **読み手に「ここは機械的に守られている」と示す** (FR-032) |

### 不変条件

- 同じ名前の印が 2 つ以上あってはならない。どちらを見るかが定まらない
- 印の直後に表がなければ失敗とする
- 印の名前は検査側が期待する 6 つのいずれかであること。未知の名前は失敗とする。
  綴りの誤りで検査対象から静かに外れることを防ぐ

## 3. 表の行 (Row)

印の直後の表から取り出した 1 行。

| 項目 | 内容 |
|---|---|
| セル | `|` で区切られた各列の値 |
| 正規化 | 前後の空白を取り除き、`` ` `` と `**` を剥がす |

表の見出し行と区切り行 (`|---|`) は行に含めない。

### 不変条件

- セルの値から装飾を剥がしたうえで突き合わせること。文書は名前を
  `` `--domain-filter` `` のように書くが、実装側の値は `domain-filter` である。
  この差を検査が吸収する
- 装飾の剥がし方は 1 か所に置くこと。対象ごとに違う剥がし方をすると、
  文書の書き方に一貫性がなくなる

## 4. 実装側の事実 (Implementation Facts)

### 取り出し方の 3 分類

| 分類 | 対象 | 性質 |
|---|---|---|
| 公開関数 | `flags`、`secret-managers`、`record-types` | 最も壊れにくい。製品の公開面をそのまま使う |
| 実行時の出力 | `metrics` | **利用者が見る名前**が得られる。内部の計測器名ではない |
| 構文木 | `dpf-operations`、`endpoints` | 他に源がない場合に限る。検査の側に閉じる |

### 計測値の取り出し

内部の計測器名と、Prometheus 形式の出力名は一致しない。

| 内部の計測器 | 出力に現れる系列 |
|---|---|
| `dns_record_changes` (Counter) | `dns_record_changes_total` |
| `dpf_api_call_duration_seconds` (Histogram) | `..._bucket` / `..._sum` / `..._count` |

**文書には出力に現れる名前を書く** (FR-017)。したがって実装側の値も出力から
採る。各計測器に 1 件ずつ記録してから収集することで、未記録の系列が現れない
問題 (FR-022) も同時に避ける。

### 不変条件

- 公開関数がある対象では、構文木を使わないこと。壊れやすい手段を不要に選ばない
- 検査のために製品コードへ公開関数を足さないこと (spec の範囲外指定)
- 構文木の読み取りは、呼び出しの引数である文字列リテラルのみを見ること。
  コメントや無関係な文字列を拾わない

## 5. 検査の境界 (Checked / Unchecked)

**文書に明記する対象**である。データではないが、本機能の中心的な約束にあたる。

| 検査する | 検査しない |
|---|---|
| 設定項目の名前と既定値 | 設定項目の意味の説明 |
| シークレット管理サービスの名前 | 認証の解決順、必要な権限、格納手順 |
| 計測値の系列名 | 計測値の意味、値が変化する契機 |
| `operation` ラベルの値 | ラベルの意味 |
| レコード種別 | 種別ごとの制約の内容 |
| 公開する経路 | 経路の振る舞いの説明 |
| | **トークンが読まれる位置** (値全体か、特定のフィールドか) |
| | エラーの分類、既知の制限 |

### 不変条件

- この境界を**文書自身に書くこと** (FR-032)。「検査されているから正しい」と
  読まれると、検査していない部分の誤りが見過ごされる
- **トークンが読まれる位置が検査できないことを、文書に明記すること。**
  本機能の発端になった指摘の中心であり、誤ると認証に失敗する。依存ライブラリの
  既定値であるため検査できない。版の固定が緩和になっている旨も併せて書く
  (research R6)

## 6. 事実と規範の食い違い (Gap)

規範が要求していて実装されていない事項。

| 項目 | 内容 |
|---|---|
| 対象 | 規範が MUST としている機能 |
| 状態 | 実装済み / **未実装** |
| 文書での扱い | 未実装なら**未実装と明記する** (FR-029) |

### 現在把握しているもの

| 事項 | 規範 | 状態 |
|---|---|---|
| ログの OpenTelemetry 形式での送出 | 原則 V (MUST) | **未実装** |
| ゾーンロックの取得・解放の計測 | (規範の要求ではない) | 未計測 |

### 不変条件

- 要求されている姿を、実装済みであるかのように書かないこと (SC-009)。
  読んだ人が動かない機能を前提に構成を組む
- 「既知の制限」として 1 か所にまとめること (FR-030)。個々の節に散らすと
  見渡せない
- **この食い違いを本機能で解消しない。** 文書は事実を書く。実装は別の機能として
  扱う (spec の範囲外指定)
