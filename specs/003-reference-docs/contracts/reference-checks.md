# Contract: 文書と実装の一致検査

**Feature**: [../spec.md](../spec.md) | **Date**: 2026-09-10

`docs/reference.md` と実装の一致を保つ検査が満たすべき契約。

---

## 検査する 7 つの組

| 印 | 文書側 | 実装側の源 | 突き合わせる値 |
|---|---|---|---|
| `<!-- reference:flags -->` | 設定項目の表 | `config.Usage()` | 設定項目の名前と既定値 |
| `<!-- reference:secret-managers -->` | 供給元の比較表 | `config.Load` | 受理される供給元の名前 |
| `<!-- reference:metrics -->` | 出力に現れる系列の表 | 宣言された計測器 + Prometheus 形式の出力 | 系列名 |
| `<!-- reference:dpf-operations -->` | `operation` の値の表 | `internal/dpf` の構文木 | `observe` の第 2 引数 |
| `<!-- reference:record-types -->` | 対応種別の表 | `provider.SupportedRecordTypes()` | 種別名 |
| `<!-- reference:endpoints-provider -->` | provider の経路の表 | `internal/webhook` の構文木 | `mux.HandleFunc` の第 1 引数 |
| `<!-- reference:endpoints-exposed -->` | exposed の経路の表 | `internal/server` の構文木 | `mux.Handle` / `mux.HandleFunc` の第 1 引数 |

## 満たすべき振る舞い

### 一致 (FR-031、SC-004、SC-005)

- 文書側と実装側を**集合として**突き合わせること (MUST)。
- 文書にあって実装にない値があれば**失敗すること (MUST)**。
- 実装にあって文書にない値があれば**失敗すること (MUST)**。
- 失敗時に、どちらにだけ存在する値かが分かること (MUST)。
  「一致しません」だけでは、文書と実装のどちらを直すのかが判断できない。

### 印の欠落 (原則 VI、research R3)

- 7 つの印がすべて存在することを、突き合わせより**先に**確かめること (MUST)。
- 印が 1 つでも欠けていれば**失敗すること (MUST)**。「対象がないので何も
  検査しない」で通さないこと (MUST NOT)。
- 印の直後に表がなければ**失敗すること (MUST)**。
- 表の行が 0 件であれば**失敗すること (MUST)**。表を空にして検査を通せない
  ようにするため。
- 同じ名前の印が 2 つ以上あれば**失敗すること (MUST)**。
- 未知の名前の印があれば**失敗すること (MUST)**。綴りの誤りで検査対象から
  静かに外れることを防ぐ。

### 検査対象の一覧の置き場所

- 期待する 6 つの印の一覧は**検査側のコードに持つこと (MUST)**。
- 文書側に持たせないこと (MUST NOT)。文書を書き換えるだけで検査を緩められる
  状態を作らない。検査を減らすには検査側の差分が必要であり、レビューに現れる。

### 実装側の取り出し方 (research R4)

- 公開関数がある対象では、**公開関数を使うこと (MUST)**。構文木を使わないこと
  (MUST NOT)。壊れやすい手段を不要に選ばない。
- 計測値は**宣言された計測器から導くこと (MUST)**。実際の出力だけから採らない
  こと (MUST NOT)。未記録の計測器が出力に現れず、追加を見逃す (SC-008)。
- 導出の規則が正しいことを、**実際の出力との突き合わせで毎回確かめること
  (MUST)**。規則は Prometheus 形式の慣習であり、こちらのコードにはない。
- 未知の種別の計測器が現れたら**失敗させること (MUST)**。接尾辞の対応を
  書き足さないまま新しい種別を足すと、その系列が検査から静かに漏れる。
- 構文木の読み取りは、**呼び出しの引数である文字列リテラルのみ**を見ること
  (MUST)。コメントや無関係な文字列を拾わないこと (MUST NOT)。
- **検査のために製品コードへ公開関数を足さないこと (MUST NOT)。** 検査の都合で
  製品の公開面を広げない。

### 実行 (FR-033)

- `go test ./...` に載ること (MUST)。`make all` と CI がそのまま実行する。
- 独立した手順にしないこと (MUST NOT)。実行を忘れられる経路を作らない。
- 外部への接続を伴わないこと (MUST)。環境変数による読み飛ばしを設けないこと
  (MUST NOT)。**常に走る。**

### 文書側の要求 (FR-032)

- 検査する範囲と検査しない範囲を、**文書自身に書くこと (MUST)**。
- **トークンが読まれる位置が検査対象外であることを明記すること (MUST)。**
  本機能の発端になった指摘の中心であり、誤ると認証に失敗する。依存ライブラリの
  既定値であるため検査できない。依存の版を固定していることが緩和になっている
  旨も併せて書くこと (MUST)。

### 事実に忠実であること (FR-029、SC-009)

- 規範が要求していて未実装の機能は、**未実装と明記すること (MUST)**。
- 実装済みであるかのように書かないこと (MUST NOT)。
- 既知の制限を 1 か所にまとめること (MUST)。

## 検査しないもの

**この一覧は文書にも書く。**

| 対象 | 理由 |
|---|---|
| 認証の解決順 | 各 SDK の内部仕様。こちらのコードに現れない |
| 必要な権限 (IAM ポリシー等) | 外部サービスの仕様。こちらから確かめられない |
| シークレットへの格納手順 | 同上 |
| **トークンが読まれる位置** | 依存ライブラリの既定値。こちらのコードには「オプションを渡していない」ことしか現れない |
| 設定項目・計測値・ラベル・経路の**意味の説明** | 散文 |
| エラーの分類と外部 API の状態コードの対応 | 網羅的に列挙できない |
| レコード種別ごとの制約の内容 | 検証ロジックの単体テストが守っている。文書との文字列一致には意味がない |
| 既知の制限の説明 | 散文 |

## この契約が隠すもの

文書を書く人から見た手順は 2 つに収まる。

1. 実装を変えたら、`docs/reference.md` の対応する表を直す
2. `make all` が通れば、印の付いた表は実装と一致している

どこから事実を取り出しているか (公開関数か、出力か、構文木か) を書き手が
知る必要はない。ただし**印のない記述は自分で確かめる必要がある**ことは、
文書に書かれているため書き手にも読み手にも伝わる。
