# Quickstart: リファレンス文書

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Date**: 2026-09-10

本書は、実装が spec の受け入れ条件を満たすことを確認する手順をまとめる。
実装コードは含まない。検査の詳細は
[contracts/reference-checks.md](./contracts/reference-checks.md) を参照。

---

## 前提

| 項目 | 内容 |
|---|---|
| Go | 1.27 以降 |
| 外部サービス | **不要**。検査は外部へ接続しない |

`GOPRIVATE=github.com/iij/dpf-go` は既存のとおり必要 (モジュールの取得に限る)。

## 1. 検査が実行されること (FR-033)

```bash
go test ./test/docs/... -v

```

| 確認 | 期待される結果 |
|---|---|
| `go test ./...` に含まれる | 含まれる |
| `make all` で実行される | 実行される |
| 環境変数による読み飛ばし | **ない**。常に走る |
| 外部への接続 | ない |

## 2. 一致していれば通ること

```bash
go test ./test/docs/... -run TestReference -v
```

6 つの組すべてで、文書側と実装側が一致していること。

| 印 | 突き合わせる値 |
|---|---|
| `flags` | 設定項目の名前と既定値 |
| `secret-managers` | 供給元の名前 |
| `metrics` | 計測値の系列名 |
| `dpf-operations` | `operation` ラベルの値 |
| `record-types` | 対応レコード種別 |
| `endpoints` | 公開する経路 |

## 3. 食い違いを検出すること (SC-004、SC-005、SC-008)

**この節が本機能の中心である。** 落ちない検査は何も守っていない。
各手順は確認後に元へ戻すこと。

### 3a. 文書だけが古い場合

| 手順 | 期待される結果 |
|---|---|
| `docs/reference.md` の設定項目の表から 1 行消す | **失敗する**。実装にあって文書にない、と報告される |
| 計測値の表から 1 行消す | **失敗する** |
| 対応レコード種別から 1 つ消す | **失敗する** |
| 経路の表から 1 行消す | **失敗する** |

### 3b. 文書だけが進んでいる場合

| 手順 | 期待される結果 |
|---|---|
| 設定項目の表に実在しない項目を 1 行足す | **失敗する**。文書にあって実装にない、と報告される |
| 計測値の表に実在しない系列を 1 行足す | **失敗する** |

### 3c. 実装だけが進んだ場合

| 手順 | 期待される結果 |
|---|---|
| 実装に設定項目を 1 つ足し、文書を更新しない | **失敗する** (SC-008) |
| 実装に計測値を 1 つ足し、文書を更新しない | **失敗する** (SC-008) |

### 3d. 失敗の内容

| 確認 | 期待される結果 |
|---|---|
| 失敗の報告 | **どちらにだけ存在する値か**が分かる |
| 「一致しません」だけの報告 | **ない**。文書と実装のどちらを直すか判断できないため |

## 4. 検査を無効化できないこと (原則 VI、research R3)

**3 と同じくらい重要である。** 検査が黙って無効になる経路がないことを確かめる。

| 手順 | 期待される結果 |
|---|---|
| 印を 1 つ消す | **失敗する**。「対象がないので成功」にならない |
| 印の直後の表ごと消す | **失敗する** |
| 表を見出し行だけにする (行が 0 件) | **失敗する** |
| 同じ名前の印を 2 つ置く | **失敗する** |
| 印の名前を綴り間違える (`reference:flag` など) | **失敗する**。静かに対象から外れない |

最後の 2 つが要点である。**綴りの誤りで検査対象から静かに外れる**経路と、
**表を空にして通す**経路を塞ぐ。

## 5. 検査の境界が文書に書かれていること (FR-032)

| 確認 | 期待される結果 |
|---|---|
| 検査される範囲の記載 | ある |
| 検査されない範囲の記載 | ある |
| **トークンが読まれる位置が検査対象外である旨** | **明記されている** |
| 上記の緩和 (依存の版を固定していること) | 記載されている |

トークンが読まれる位置は、本機能の発端になった指摘の中心でありながら
検査できない。「検査されているから正しい」と読まれないよう、明示する。

## 6. 事実に忠実であること (FR-029、SC-009)

| 確認 | 期待される結果 |
|---|---|
| ログの OpenTelemetry 形式での送出 | **未実装と明記されている** |
| ゾーンロックが計測されていないこと | 明記されている |
| 規範が要求する姿を実装済みのように書いた箇所 | **0 件** |
| 既知の制限のまとまり | 1 か所にある |

`--otlp-endpoint` の説明が「ログ・計測値・追跡情報を送出する」と読めては
ならない。効くのは計測値と追跡情報のみである。

## 7. US1 の受け入れ (SC-001、SC-002)

機械では確かめられない。**人が読んで判断する。**

| 確認 | 期待される結果 |
|---|---|
| 供給元ごとに「識別子に渡すもの」「トークンが読まれる位置」「認証の手段」「必要な権限」 | 4 項目すべてが記載されている |
| Vault が読むフィールド名 | 記載されている。変更できるかどうかも分かる |
| `--dpf-token-secret-endpoint` の供給元ごとの意味 | 違いが明示されている |
| 格納の手順 | 供給元ごとに記載されている |
| 供給元をまたいだ比較 | ある。1 つを選ぶのに各節を順に読む必要がない |

実装コードを読んだことのない人に、文書だけを見て 4 つの供給元それぞれで
起動できるかを試してもらうのが最も確かな検証である。
