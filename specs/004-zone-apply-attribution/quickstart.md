# Quickstart: 動作確認の手順

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Date**: 2026-09-15

本書は、実装が spec の受け入れ条件を満たすことを確認する手順をまとめる。
実装コードは含まない。詳細は [contracts/](./contracts/) と
[data-model.md](./data-model.md) を参照。

---

## 前提

| 項目 | 内容 |
|---|---|
| Go | 1.27 以降 |
| DPF | 破壊的操作を行ってよい**検証用ゾーン**と、そのゾーンを操作できるアクセストークン |

**警告**: 本書の手順は DNS レコードを実際に変更する。本番ゾーンでは実行しない。

001 の検証用ゾーンをそのまま使える。本機能のために新しいゾーンは要らない。

---

## 1. 記録が要求に載ること (単体)

DPF へ到達せずに確かめられる範囲。

| 確認 | 期待される結果 |
|---|---|
| 一括更新の要求を組み立てる | 説明に `external-dns-iij-dpf-webhook` が入る (FR-002) |
| 変更セットの内容を変えて組み立てる | **説明が変わらない** (data-model 1 の不変条件) |
| ゾーンを変えて組み立てる | 説明が変わらない |
| レコードのコメント | 説明を書き込まない。既存のコメントが逐語的に保たれる (FR-007) |
| 認証情報 | 説明に含まれない (FR-004、SC-003) |

---

## 2. 記録が履歴に現れること (実環境)

**ここが本機能の中心である。** 要求に載せたことと、DPF が履歴に残すことは別である。

```bash
# 検証用ゾーンに対して実行する
DPF_E2E_TOKEN_FILE=<token> DPF_E2E_ZONE=<zone> go test ./test/e2e/... -run TestApplyAttribution -v -count=1
```

| 確認 | 期待される結果 |
|---|---|
| 変更を適用した直後に履歴を読む | 最新の履歴の説明に `external-dns-iij-dpf-webhook` が含まれる (FR-001、SC-002) |
| 説明の長さ | DPF に拒否されない。**記録の付与を理由に失敗する反映が 0 件** (SC-005)。28 < 80 であり拒否される理由はないが、実際に投げて確かめる |
| 説明で履歴を絞り込む | `external-dns-iij-dpf-webhook` を語として検索し、当該の反映が引ける (research R2) |
| 連続して 2 回適用する | **2 件とも**記録が付く。記録の付かない反映がない (SC-002) |
| 適用前に存在した履歴 | **書き換えられていない** (FR-008) |

**この節を省かない。** 上限は `maxLength: 80` としてスキーマに宣言されており、
28 オクテットが収まることは投げる前に分かる (research R5)。それでも実環境で
確かめるのは、**説明が要求に載ることと、DPF が履歴として保持することが別の事実**
だからである。前者は単体テストで足りるが、後者は実環境でしか分からない。

## 3. 人手の変更と区別できること (実環境・手作業)

| 手順 | 期待される結果 |
|---|---|
| DPF コンソールから人手でレコードを 1 件変更し、反映する | その履歴には本サービスの記録が付かない |
| 続いて本サービスから変更を適用する | その履歴には記録が付く |
| 履歴を並べて見る | 両者を 100% 見分けられる (SC-001) |

**この項目は機械化しない。** DPF コンソールの操作を伴うため。機械化しない理由を
実装時にテストの冒頭へ記す (001 の quickstart と同じ方式)。

---

## 4. 既存の振る舞いを壊していないこと

本機能は 001 の適用経路に乗る。**壊していないことの確認が、付けたことの確認と
同じだけ重要である。**

| 確認 | 期待される結果 |
|---|---|
| 同一の変更セットを繰り返し適用する | DNS の最終状態が変わらない (001 FR-010、SC-004) |
| 管理対象外のレコード | 変更・削除されない (001 FR-009) |
| レコードのコメント | 逐語的に保たれる (FR-007) |
| 反映完了前に成功を返さない | 従来どおり (001 FR-011) |
| 適用の所要時間 | 記録の付与で増えない。**API 呼び出しは増えていない** (research R1) |

既存の e2e (`TestLifecycle`、`TestUnmanagedRecordsUntouched`、`TestScale`) が
そのまま通ることをもって確認する。
