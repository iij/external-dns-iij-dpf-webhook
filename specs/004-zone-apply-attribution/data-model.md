# Data Model: ゾーン反映の実行者を DPF の記録に残す

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Date**: 2026-09-15

本機能が加える実体は 1 つだけである。001 の実体 (正規化名、管理対象範囲、
ゾーン索引、DNS レコード、変更セット) には変更を加えない。

---

## 1. 反映の記録 (Apply Attribution)

ゾーンの反映操作に添える短い説明。DPF の履歴に残る。

| 属性 | 内容 |
|---|---|
| 値 | 固定文字列 `external-dns-iij-dpf-webhook` |
| 長さ | 28 オクテット。**入力によって変動しない** (research R4) |
| 上限 | **80 オクテット** (DPF の共通スキーマ `Description`、research R5) |
| 既定 | 省略時は空文字列。本機能より前の反映は履歴上で説明が空である |
| 生成 | `internal/dpf` の定数。上位層から渡さない (research R6) |
| 載せる先 | 一括更新の要求に添える説明 (research R1) |

**不変条件**: 値は呼び出しごとに変わらない。変更セットの内容、ゾーン、時刻の
いずれにも依存しない。

**この実体は DNS レコードではない。** ゾーンのレコードデータとは別に保持され、
名前解決に影響しない (FR-005)。したがって次が成り立つ。

- 記録が付いても、同一の変更セットの再適用で DNS の最終状態は変わらない
  (001 FR-010)
- 投入前ガード (001) の検査対象にならない。ガードはレコードの増減を見る

---

## 2. 記録が現れる場所

DPF はゾーンの反映を履歴として保持する。1 件の履歴は次を持つ。

| 属性 | 内容 | 本サービスとの関係 |
|---|---|---|
| 反映時刻 | 反映が行われた時刻 | ログとの突き合わせに使える (001 FR-020) |
| 説明 | 反映に添えられたコメント | **ここに記録する** |
| 編集者 | DPF が資格情報から決める値。null を取りうる | **本サービスは設定しない** (research R3) |

**編集者では足りない理由**: 編集者が示すのは「どの DPF アカウントが操作したか」
までである。人が使うアカウントと本サービスのアカウントが同じ場合、あるいは複数の
自動化がアカウントを共有している場合に区別がつかない。どのソフトウェアが実行したかは、
そのソフトウェア自身が名乗るしかない。

**読み戻せる**: 履歴は API から取得でき、**説明を語で絞り込める**
(`KeywordsDescription`)。受け入れ確認を人手の目視に頼らず、機械的な表明として
書ける (research R2)。

---

## 3. 記録を付ける範囲

| 対象 | 扱い |
|---|---|
| 本サービスが行う反映 | 記録を付ける (FR-001) |
| 反映を伴わない操作 (空の変更セット) | 反映そのものが行われないため、記録も残らない |
| 過去の反映の記録 | **書き換えない** (FR-008)。履歴は追記のみ |
| 他者が付けた記録 | **書き換えない** (FR-008) |
| レコード単位のコメント | **本機能の対象外** (FR-007)。001 のマージが従来どおり逐語的に保つ |

**複数ゾーンにまたがる変更セット**: 001 の FR-042 により、適用はゾーンごとに
行われる。反映もゾーンごとに起きるため、記録は**反映したすべてのゾーンに付く**
(FR-003)。特別な扱いを要しない。
