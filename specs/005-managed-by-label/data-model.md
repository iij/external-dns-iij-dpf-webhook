# Data Model: レコードに管理者の印を付ける

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Date**: 2026-09-16

本機能が加える実体は 1 つである。001 の実体 (正規化名、管理対象範囲、ゾーン索引、
DNS レコード、変更セット) には変更を加えない。

---

## 1. 管理者の印 (Managed-By Label)

レコードに付ける名前と値の対。

| 属性 | 内容 |
|---|---|
| 名前 | `managed-by` (固定) |
| 値 | `external-dns-iij-dpf-webhook` (固定、28 文字) |
| 生成 | `internal/dpf` の定数。**値は 004 の反映の記録と同じ定数**とする (research R6) |
| 保存先 | DPF のレコードのラベル |

**不変条件**: 名前も値も固定である。レコードの内容、ゾーン、時刻のいずれにも
依存しない。

**この実体は DNS のデータではない。** 名前解決に影響せず、ExternalDNS へも渡らない
(research R5)。したがって次が成り立つ。

- 印の付与によって DNS の最終状態が変わらない (SC-006)
- 同一の変更セットの再適用で結果が変わらない (001 FR-010)
- ExternalDNS が比較する 4 つの条件のいずれにも現れないため、差分の振動を起こさない

---

## 2. レコードのラベルの制約

DPF がレコードのラベルに課す制約 (research R1)。

| 項目 | 値 | 典拠 |
|---|---|---|
| 個数の上限 | **10** | `openapi.json` の `RecordLabels.maxProperties` |
| 値の長さ | 1〜63 文字 | 同 `additionalProperties` |
| 名前・値の文字種 | 英数字と `.` `-` `_` | DPF マニュアル「ラベルの共通ルール」 |

**ラベルは毎回上書きする。** 本 provider が書くレコードのラベルは、常に印 1 つだけに
なる。したがって**上限 (10) に触れる経路が存在しない** (research R2)。

上限に達した場合の扱いを定める必要がない。**設定しない分岐は壊れない。**

---

## 3. 印を付ける対象

001 のマージは 3 段で構成される。印を付けるのは**段 3 の対象だけ**である。

| 対象 | 印 | 要件 |
|---|---|---|
| 作成したレコード | 付ける | FR-001 |
| 更新したレコード | 付ける。印が無かったものにも付く | FR-002 |
| ExternalDNS の所有権 `TXT` | **付ける。** 変更セットに通常のレコードとして入る | FR-003 |
| 触らないレコード | 付けない。ラベルも内容も変えない | FR-003 |
| `SOA`・ゾーン apex の `NS` | 付けない。変更セットに入らない | — |
| 削除するレコード | 対象外 | — |

### 既にラベルを持つレコードの扱い

| 状態 | 結果 |
|---|---|
| ラベルが無い | 印だけになる |
| 他のラベルがある | **印だけになる。他のラベルは失われる** (PC-001) |
| 既に印が付いている | 変わらない (FR-005) |
| `managed-by` に別の値 | 自身の名前になる |

**不変条件**: 本 provider が書くレコードのラベルは、**常に印 1 つだけ**である。
入力の状態によらず同じ状態へ収束する。

**触らないレコードのラベルは変えない** (FR-003)。上の表は変更セットに含まれる
レコードだけの話である。

### マップを差し替える

投入集合の土台は反映済みレコードのラベルへの**参照**である (`toOverwrite`)。
**新しいマップを代入するため、元のマップに触れない。** 写しを作る手当ても要らない
(research R3)。

---

## 4. 絞り込み

印が付いていることで、DPF のレコード一覧をラベルで絞り込める (research R4)。

| 用途 | 使い方 |
|---|---|
| 運用者 | DPF の機能として、印で絞った一覧を得る (FR-006) |
| 受け入れ確認 | 絞り込んだ一覧を取得し、管理外のレコードが含まれないことを表明する (SC-003) |

**本 provider は通常の動作で絞り込みを使わない。** 印を読み返して振る舞いを変える
ことはしない。読み取りは検証のためだけに実装する (004 のゾーン反映履歴と同じ扱い)。
