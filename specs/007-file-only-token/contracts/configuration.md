# Contract: 起動時の設定 (トークンの供給元)

**Feature**: [../spec.md](../spec.md) | **Date**: 2026-10-06

本機能が変える外部契約は**コマンドライン引数**だけである。ExternalDNS webhook API の
外形 (経路、メディアタイプ、要求・応答の形) は変わらない。

## 受け付けるフラグ (トークン関係)

| フラグ | 必須 | 既定 | 内容 |
|---|---|---|---|
| `--dpf-token-file` | **必須** | (なし) | アクセストークンを収めたファイルのパス |

## 受け付けないフラグ

指定すると**起動に失敗する**。終了コードは非 0。標準エラー出力に、受け付けなかった
フラグの名前が現れる。

| フラグ | 状態 | 理由 |
|---|---|---|
| `--dpf-token` | 従来から存在しない | プロセス一覧から読める |
| `--dpf-token-secret-manager` | **本機能で廃止** | 供給元をファイルに限った (constitution v3.0.0) |
| `--dpf-token-secret-id` | **本機能で廃止** | 同上 |
| `--dpf-token-secret-endpoint` | **本機能で廃止** | 同上 |

## 参照しない環境変数

| 環境変数 | 理由 |
|---|---|
| `DPF_API_TOKEN` | 従来どおり。環境変数からトークンを受け取らない |
| `VAULT_*`、`AWS_*`、`AZURE_*`、`GOOGLE_APPLICATION_CREDENTIALS` など | これらを読む SDK をリンクしない。設定されていても挙動は変わらない |

## 起動時の判定

| 入力 | 結果 |
|---|---|
| `--dpf-token-file` なし | 起動失敗。メッセージに `--dpf-token-file` を含む |
| `--dpf-token-file=<path>` | 起動する |
| `--dpf-token-file=<path>` と廃止フラグの併用 | 起動失敗。メッセージに廃止フラグの名前を含む |
| 廃止フラグのみ | 起動失敗。メッセージに廃止フラグの名前を含む |

## `--help`

- `-dpf-token-file` が現れる
- `-dpf-token-secret-manager`、`-dpf-token-secret-id`、`-dpf-token-secret-endpoint` は
  現れない
- 末尾の案内は「アクセストークンは --dpf-token-file で与えます。環境変数と引数から
  トークンを受け取る経路は用意していません。」の趣旨とする

## 外向きの通信

本サービスが接続する先は次に限られる。シークレット管理サービスは含まれない。

| 接続先 | 条件 |
|---|---|
| DPF API | 常に |
| 名前解決 | 常に |
| OTLP 送出先 | `--otlp-endpoint` を指定した場合のみ |
