# Data Model: アクセストークンの供給元をファイルに限る

**Feature**: [spec.md](./spec.md) | **Date**: 2026-10-06

本機能は永続データを持たない。変わるのは**起動時の設定の形**だけである。

## config.DPF (DPF API への接続設定)

| 項目 | 変更 | 内容 |
|---|---|---|
| `Endpoint` | 変更なし | DPF API のエンドポイント。空なら dpf-go の既定値 |
| `TokenFile` | **必須になる** | トークンを収めたファイルのパス。空なら起動しない |
| `SecretManager` | **削除** | — |
| `SecretID` | **削除** | — |
| `SecretEndpoint` | **削除** | — |
| `UsesSecretManager()` | **削除** | — |

### 検証規則

| 条件 | 結果 |
|---|---|
| `TokenFile` が空 | `ErrMissingRequired`。起動を中止する |
| `TokenFile` が空でない | `config.Load` は受理する。ファイルの存在・可読性は設定の解釈では確かめない |
| 廃止したフラグを指定 | フラグの解釈の段階で `ErrInvalid`。`build()` には到達しない |

ただし起動処理の続きで DPF クライアントを作る際、dpf-go v0.6.0 の `NewClient` が
設定の誤りを早く知らせるために**トークンを 1 度取得する**。このため、起動時に
ファイルが読めない・空であれば起動に失敗する (実装時に確認、T006)。これは現行の
振る舞いであり、本機能では変えない。kubelet はボリュームをコンテナの起動前に
マウントするため、Secret のマウントでこれが問題になることはない。

## トークンファイル

| 性質 | 内容 |
|---|---|
| 内容 | ファイル全体がトークン。JSON 等として解釈しない |
| 整形 | 前後の空白を取り除く |
| 読み取り | 起動時に 1 度 (dpf-go の検証)。以後は DPF API を呼ぶたびに読み直す。キャッシュしない |
| 空 / 空白のみ | 起動時なら起動失敗。起動後なら要求ごとの取得失敗 (恒久的な失敗)。DPF へ要求を送らない |
| 読めない | 取得失敗 (恒久的な失敗)。外へ返すメッセージは定型文「アクセストークンを取得できませんでした」に置き換わり、**ファイルのパスも内容も含まない** |

これらは 001 の FR-034・FR-037〜FR-039 で定めた振る舞いであり、本機能では変えない。
空のファイルの扱いは dpf-go v0.6.0 の振る舞いに依る。`utils.TokenFromFile` は
前後の空白を除いた空文字列を返し、dpf-go のクライアントがそれを `ErrTokenRequired`
として扱う。本機能で新たな判定は足さない。この振る舞いはテストで固定する
(quickstart 手順 2)。
